แนวทางภาพ: **โลกทะเลที่เป็นมิตร อ่านง่าย และมีรายละเอียดที่ตอบสนองกัน** ฉากมีความลึกและจังหวะช้า ส่วนพื้นที่อ่านโจทย์และปุ่มมีความนิ่งและชัดเจน หน้า Admin ใช้ภาษาออกแบบเดียวกัน แต่จัดพื้นที่เพื่อทำงานข้อมูลได้สะดวก

## โลกที่มีชีวิตตามระดับความสนใจ

1. **พื้นหลัง:** คลื่นหลายระยะ เมฆ และเรือขยับเบา ๆ ด้วยจังหวะต่างกัน
2. **เหตุการณ์:** ปลาเล็กกระโดดเป็นครั้งคราว เกิด splash แล้วเป็นวงน้ำ; นกบินผ่านเป็นบางครั้ง
3. **ผลต่อเนื่อง:** Nimo เอียงตัวมองปลาเมื่อว่าง; เมื่อเรียนผ่าน server ยืนยันแล้ว เส้นทางเกาะใหม่สว่างและตัวละครฉลองครั้งเดียว

ค่าเริ่มต้นที่เสนอสำหรับปลา: desktop เว้นสุ่ม 12–24 วินาที, mobile 24–40 วินาที; ครั้งละ 1 ตัว สูงสุด 2 วงน้ำ; ไม่อยู่เหนือหัวข้อ/ปุ่ม และไม่มีเสียงอัตโนมัติ เหตุการณ์ต้องหยุดเมื่อกล้องฉากกำลังเดินทาง ฉากไม่อยู่ในจอ เปิด dialog ซ่อนแท็บ กดพัก หรือเปิด reduced motion ตัวเลขนี้เป็นค่าเริ่มต้นสำหรับทดสอบ ไม่ใช่ค่าที่วัดจาก Duolingo

## Nimo โมเดลเดิม ทำได้เป็นขั้น

ระยะแรกใช้ภาพเดิมจริง: เปลี่ยนตำแหน่ง/เอียง/ยุบตัวเล็กน้อย ข้อความสั้น ไอคอนสถานะ และภาพพายเรือที่มีอยู่ ให้แต่ละปฏิกิริยาต่างกันชัดเจน อย่าอ้างว่าภาพ PNG แบนกะพริบตาหรือขยับปากแยกส่วนได้

หากต้องการตา ปาก หู และมือขยับจริง ให้เตรียม layer หรือ pose เพิ่มจากตัวละครเดิม โดยรักษาหน้า สัดส่วน สี ลายเส้น และเสื้อผ้าเดิม นี่เป็นงานเตรียม asset ของโมเดลเดิม ไม่ใช่เปลี่ยนตัวมาสคอต และไม่จำเป็นต้องเพิ่ม 3D engine

## ใช้ ASP.NET MVC ตามโครงสร้างที่มี

- **Models/ViewModels:** ข้อมูลคอร์ส ความก้าวหน้า โหมด guest/account และสถานะที่ Views ต้องแสดง
- **Controllers:** รับ GET/POST เลือกคอร์ส เปิดบทเรียน รับคำตอบ ตรวจ ModelState แล้วส่ง View/JSON ตามงานเดิม
- **Services/SQL:** คงการให้คะแนน รางวัล การปลดล็อก และบันทึกผลบน server
- **Views/Razor/Tag Helpers/Partials:** ประกอบ layout, navigation, button, form, lesson, feedback, mascot และฉาก
- **CSS:** ภาพ responsive และแอนิเมชันที่รู้เส้นทางล่วงหน้า
- **JavaScript/WAAPI:** การเปลี่ยน state บนหน้าจอ ปฏิกิริยา Nimo และ event scheduler; GSAP ใช้เฉพาะฉากที่มีอยู่แล้ว

ไม่ต้องย้ายไป React/Next.js หรือเพิ่มเกมเอนจิน แผนนี้ถือว่า CSS/JavaScript เสริม Razor ใช้ได้ตามโครงสร้างที่โปรเจกต์ใช้อยู่ แต่ไม่ได้ยืนยันข้อกำหนดรายวิชานอกเหนือจาก ASP.NET MVC ที่ผู้ใช้ระบุ

## ก่อนส่งงานแต่ละรอบ

ตรวจภาพที่ 360/390/768/1024/1440px, zoom 200%, ภาษาไทยยาว, keyboard/Tab/Escape, guest/account, first-time/returning และ reduced motion ต้องผ่านทุกเส้นทางหลักก่อนเพิ่มรายละเอียดฉาก

ตรวจ flow: หน้าแรก → เลือกคอร์ส → login เมื่อจำเป็น → กลับคอร์สเดิม → เปิดเกาะ → อ่าน/ตอบ → ผล/XP → เกาะถัดไป → กลับมาเรียนต่อ; รวมตอบผิด ทบทวน คอร์สสุดท้าย เปลี่ยนคอร์ส offline และ server error

เป้าหมายความลื่นไหลเป็นเกณฑ์รับงาน ไม่ใช่ผลตรวจปัจจุบัน: จอ 60Hz ให้ animation อยู่ใกล้งบ 16.7ms/frame บนอุปกรณ์เป้าหมาย, กดปุ่มแล้วมี feedback ภายใน 100ms, ไม่ให้ฉากทำให้ตำแหน่งปุ่มกระโดด และไม่มี timer/animation ค้างหลังออกหน้า

ทุก PR แนบภาพ desktop/mobile และคลิป interaction ที่เปลี่ยน, ระบุ MVC files ที่แก้ และใช้ tokens/classes กลาง แก้ token แทนการคัดลอกปุ่มใหม่ไปอีกไฟล์
